# Datos, términos y semántica

## ChronoGraph

Repositorio público oficial: https://github.com/bit-ml/ChronoGraph . El archivo LICENSE del repositorio contiene Apache2.0; esto se verifica para su código y no se transforma automáticamente en una licencia separada de todos los archivos de datos enlazados. La copia local de telemetría se identifica por SHA256 en los manifiestos y la investigación histórica conserva su procedencia. No se publica una copia externa del dataset en este repositorio.

CPU: se conserva la escala `cpu_usage` publicada; no se convierte a porcentaje ni se afirma una asignación de núcleos sin metadatos suficientes. Memoria: `container_memory_usage_bytes`, en bytes. Resolución:1800s entre registros salvo un salto de108000s tras la fila5907, dentro del período de validación. Las ventanas se separan en ese salto. 8005 tiempos; cohorte fuente28, destino32; el muestreo espacial depende de topología y hash. La tarea predice el uso observado, no una demanda latente libre de restricciones de capacidad. El grafo estático publicado se trata como metadato conocido; no se verificó disponibilidad temporal de cada arista. Esto limita una interpretación de despliegue online, aunque no se utilicen errores de prueba para elegir el subgrafo.

## Alibaba2022

Fuente oficial: https://github.com/alibaba/clusterdata/tree/master/cluster-trace-microservices-v2022 . La documentación oficial se conserva con hash en `docs/ALIBABA_2022_README_OFICIAL.md`; el README raíz invita al uso para investigación/estudio. No se observó una licencia independiente que garantice redistribución pública ilimitada: los archivos brutos y el paquete local no se deben subir automáticamente como datos con licencia propia.

Se descargaron exactamente48 objetos `MSMetricsUpdate_0..47.tar.gz` desde el almacenamiento OSS enlazado por el propietario:17,890,753,336bytes. Todos pasaron Content-MD5 y se registraron con SHA256 durante la transferencia. El límite previo fue1GiB por objeto, dos trabajadores, tres intentos y reserva50GiB. La auditoría posterior comprueba tamaños/manifiestos y hashes de los agregados; no afirma haber releído otra vez18GB para validar hashes ya calculados al descargar.

Los archivos contienen675,424,445 filas CSV. Se eligen32 servicios con cobertura de todos los tiempos del objeto inicial, ordenados por SHA256. Esta es selección por disponibilidad de calibración y no por error. Los valores publicados de CPU/memoria están normalizados por min–max; no se conocen aquí los límites físicos originales. La documentación no especifica suficientemente el ámbito temporal de los mínimos/máximos originales del proveedor. No se certifica ausencia de información global en ese preprocesamiento de publicación, que no podemos reconstruir sin valores físicos originales. Nuestra calibración adicional usa solo el prefijo declarado. Sus MAE/RMSE son errores en utilización normalizada agregada y **no** en bytes o núcleos. El CSV bruto conserva el identificador técnico armonizado `container_memory_usage_bytes` para indexar el segundo recurso; ese identificador no establece la unidad de Alibaba. El CSV auditado añade `target_units` y `target_semantics`, y `results/analysis/target_semantics.csv` hace explícita la correspondencia por dataset.

La inspección registra1440 minutos distintos consecutivos, paso60000ms. Se conservan filas de pods con CPU y memoria numéricos y finitos simultáneamente. Para cada servicio/tiempo se promedian esas filas de pods; después se promedian treinta tiempos dentro de [a,a+30min), disponible solo al cierre. No se usa el valor de un intervalo futuro para completar el anterior. Un bin con menos de treinta tiempos válidos queda NaN en ambos recursos. Esto cambia la tarea respecto a ChronoGraph: promedio del intervalo frente a lectura puntual y servicios compuestos por pods frente a la métrica publicada por servicio.

La auditoría independiente reconstruye el agregado a partir de sumas y conteos por timestamp: diferencia máxima4.44e−16, tolerancia1e−12. Las cuatro entradas faltantes pertenecen a dos bins de calibración: MS_73346,bin4,28 minutos; MS_26090,bin9,29 minutos; dos recursos cada uno. Se excluyen de medias/escalas y pares MASE de calibración; no se inventan objetivos. El bloque de evaluación tiene36 tiempos completos por servicio.

Los primeros12 bins (6h) calibran media/escala/mediana y MASE, y se evalúan los36siguientes (18h). No se ajustan pesos, hiperparámetros ni decisiones de selección sobre Alibaba. Solo se transfieren los modelos fuente principales L12/H1. Se excluye la GRU con grafo, pues no se descargó grafo externo, y no se inventa uno. La identidad almacenada en el NPZ no se usa para afirmar evidencia estructural.

Un día y32 servicios seleccionados no validan una población de centros de datos. El MASE externo tiene solo12 bins de referencia, dos de ellos parcialmente ausentes para un servicio cada uno; su denominador puede ser inestable. Se reportan MAE/RMSE y resultados desfavorables, sin convertir una clasificación de modelos en ahorro real de recursos. `results/data_verification.json` conserva el detalle exacto.

## Disponibilidad y código de terceros

PatchTST usa código oficial `yuqinie98/PatchTST`, commit204c21efe0b39603ad6e2ca640ef5896646ab1a9, con licencia Apache2 conservada y hashes de cada archivo. Las clases locales DLinear/NLinear/GRU/GRU-D se describen como implementaciones o adaptaciones, sin atribuirles fidelidad de entrenamiento a todos los autores originales. Los paquetes y versiones ejecutados constan en `configs/environment_pip_freeze.txt`.

La entrega permanece local: datos procesados, predicciones, pesos, scripts y manifiestos permiten revisión. Un repositorio público o DOI persistente aún debe crearse por decisión de los autores y respetando condiciones de datos/código. La licencia del código nuevo, financiación y autoría requieren confirmación humana. La declaración del artículo distinguirá disponibilidad local real de una publicación pública todavía pendiente.
